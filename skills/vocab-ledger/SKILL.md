# vocab-ledger

把「这次哪里不会」记成一条可回溯的记录，一周一张纸地复习。

## 何时用

命中任意一条就加载：

- 用户发来英语作文、中译英、英译中、听写、阅读笔记，要求批改
- 用户说「记一下这个词」「以后帮我记生词」
- 用户要「生词报告」「周报」「把这周的生词整理出来」

不适用：纯口语聊天、与英语学习无关的翻译需求。

## 三步流程

### 第一步：判断这算不算「生词」

算：

- 用户写错、拼错、用错搭配的词
- 用户卡住、含糊带过、明显靠猜的地方
- 批改中给出更好表达时，那个替代词/短语

不算：

- 用户本来用对了的常见词
- 你为了显得有料而补充的生僻词

宁少勿多：一周 10–15 个能背完，30 个背不完。

### 第二步：落库

先看本仓库的 `AGENTS.md`（工作约定）与 `SPEC.md`（字段定义），再执行：

```bash
python vocab.py add --file seed/<week>.json     # 批量，推荐
```

单个词用行内参数：

```bash
python vocab.py add "resilient" --zh "有韧性的" --pos adj. \
  --tag "写作搭配" --source "2026-W47 作文批改" --note "写成 resistent"
```

### 第三步：用户说「会了」时划掉

```bash
python vocab.py learn resilient        # 斩：背完了，不再出现在表二（别名 kill）
python vocab.py unlearn resilient      # 又忘了，放回去（note 保留）
python vocab.py star resilient         # 收藏：进收藏夹，斩了也还在
python vocab.py unstar resilient
```

**这是他唯一的进度信号，你不要替他按。**

要点：`note` 必须具体到「写成了什么、错在哪个介词/时态」；重复导入是安全的（幂等），不要因为担心重复而跳过第二次批改。

### 第四步：回话

三行以内：记了几个词、几条错因、最该先背哪几个。不要贴 JSON，不要复述报告全文。

## 不要做

- 不要手改 `learned`；也不要替用户判定他会了
- 不要覆盖用户已有的释义与例句
- 不要编造音标；没把握就留空
- 不要自己搞一套新字段——要增字段先改 SPEC 版本
